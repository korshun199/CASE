# Аппаратный паспорт Orange Pi 4 Pro

Статус документа: первичная фиксация.  
Дата фиксации: 2026-10-13.

Документ нужен как постоянная точка отсчёта проекта CASE. Перед подключением внешних устройств сведения из этого файла необходимо сопоставлять с фактической ревизией платы и текущим выводом Linux.

## 2. Интерфейсы по официальному руководству

| Интерфейс | Зафиксированное назначение | Ограничение до проверки |
|---|---|---|
| HDMI TX 2.0 | вывод изображения до 4K@60 | подключать только монитор/приёмник; это не вход видеосигнала |
| MIPI-DSI | 4-полосный интерфейс дисплея | не подключать без проверки конкретного дисплея, распиновки и напряжений |
| MIPI-CSI | один 2-полосный и один 4-полосный интерфейс камеры | не подключать камеру без документации модуля и схемы |
| USB | 1 × USB 3.0 Type-A и 3 × USB 2.0 Host | HDMI-оцифровщик использовать как внешний USB/UVC-источник только после проверки его фактического режима |
| Ethernet | Gigabit Ethernet, PHY YT8531CA | сетевые параметры не менять без отдельного согласования |
| Wi-Fi/Bluetooth | комбинированный модуль Wi-Fi 6 + Bluetooth 5.4/BLE | фактическое наличие и драйверы проверяются в Linux |
| Аудио | один разъём 3.5 мм, вход/выход | не относится к первому прототипу |
| microSD/uSD | карта загрузки, заявлена поддержка до 128 ГБ | запись карты выполнять только с подтверждением цели |
| eMMC | опциональный модуль 16/32/64/128 ГБ | наличие на конкретной плате не подтверждено |
| M.2 M-Key | NVMe через PCIe 3.0 | наличие накопителя и фактическая разводка не подтверждены |
| 40-pin | GPIO и функции UART, I²C, SPI, PWM и другие | электрические уровни и назначение каждого контакта проверять по таблице платы |

## 3. Зафиксированный UART

Официальное руководство указывает доступный UART7 на 40-pin разъёме:

| Сигнал | Контакт 40-pin |
|---|---:|
| UART7-TX | 8 |
| UART7-RX | 10 |

UART в Linux по документации отключён по умолчанию и включается через sudo orangepi-config → System → Hardware. До отдельного согласования UART не включать и внешние сигналы не подавать.

## 4. Питание и механика

Официальное руководство и дополнительные материалы указывают питание через USB Type-C 5 В. Точный требуемый ток, допустимый источник и вариант питания от аккумуляторного блока должны быть подтверждены по разделу питания руководства и измерениями до проектирования кейса.

В проекте запрещено считать наличие USB Type-C доказательством правильной распиновки аккумуляторного блока. Аккумулятор, DC-DC-преобразователь, предохранитель, выключатель и цепь зарядки проектируются отдельно.

## 5. Фактически подтверждено при первом запуске

По SSH-баннеру после загрузки записанного Debian Bookworm Server:

- имя системы: orangepi4pro;
- Debian Bookworm с ядром 5.15.147-sun60iw2;
- доступная память: 3.76G;
- температура CPU на момент входа: 41°C;
- SSH работает;
- плата получила адрес в локальной сети.

Локальный IP и MAC-адрес намеренно не записываются в проектную документацию: это device-specific данные и сетевые идентификаторы конкретного экземпляра.

## 6. Что ещё нужно проверить read-only

До создания конфигурации платы и подключения периферии нужно получить из самой системы:

- /proc/device-tree/model и /proc/device-tree/compatible;
- lscpu, точный объём памяти и частоты;
- lsblk, наличие eMMC/NVMe и точку загрузки;
- ip -br addr и состояние Ethernet/Wi-Fi/Bluetooth;
- /dev/video*, /dev/dri/* и состояние DRM/HDMI;
- /dev/i2c-*, /dev/spidev*, /dev/ttyS*;
- температурные зоны и throttling;
- активные и failed systemd-сервисы;
- параметры загрузчика из /proc/cmdline;
- сообщения ядра по HDMI, USB, MMC, Ethernet и камерам.

До получения этого отчёта пункты выше считаются непроверенными.

## 7. Правила подключения для CASE

1. Сначала определить разъём и функцию по этому паспорту и официальной схеме.
2. Затем проверить напряжение и направление сигнала конкретного модуля.
3. Для первого включения подключать только питание, Ethernet/SSH и HDMI-монитор.
4. HDMI-оцифровщик, камеры, датчики и GPIO подключать по одному, с отдельной проверкой результата.
5. Не переносить распиновку с Orange Pi 4, 4 LTS, 4A, 5 или другой платы.
6. Считать раздельными фактами: обнаружение устройства, наличие драйвера, корректное чтение данных и рабочую функцию приложения.
